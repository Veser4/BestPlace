**1. Цель**

Целью данного архитектурного репозитория является предоставление детального описания архитектуры сервиса BestPlace. Документ служит единым источником правды для разработчиков команды, фиксируя функциональные и нефункциональные требования, доменную модель и границы системы

**2. Область применения**

Сервис BestPlace представляет собой веб-приложение для поиска, добавления и категоризации уникальных и эстетичных мест. Система охватывает пользовательский интерфейс, модуль модерации контента и панель администрирования для назначения ролей пользователей

**3. Технический контекст**

BestPlace будет адаптивным веб-приложением с фокусом с mobile-first. Система интегрируется со сторонними сервисами, например Яндекс Карты, Google Maps для визуализации объектов и передачи GPS для построения маршрутов. Архитектура ориентирована на событийно-управляемое взаимодействие и разделение зон ответственности по ролям

**4. Основные функции**

- Поиск и фильтрация локаций: поиск по названию/описанию, фильтрация по категориям - "Заброшенное", "Для пикника" и тд. Отображение на карте с учетом геопозиции
- Просмотр карточки места: ознакомление с детальным описанием, фотографиями, условиями доступа и точными GPS
- Постановка маршрута;
- Избранное: сохранение понравившихся мест
- Черновики: создание черновиков
- Поделиться: отправка новых локаций на проверку с фото и описанием места
- Модерация и жалобы: проверка заявок модераторами и обработка жалоб
- Администрирование: управление справочником категорий, ролями и блокировками пользователей

**5. Проблемы и ограничения**

- Точность геоданных: необходимость работы с объектами на природе, у которых нету точного почтового адреса
- Качество контента: риски дублирования мест, спама, неактуальной информации и загрузки запрещенных медиафайлов
- Внешние зависимости: доступности сторонних API у карт 
- Юридические требования: необходимость соблюдения законодательства РФ (ФЗ-152) в части хранения и обработки персональных данных
