
**Дата:** 7 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Для команды BestPlace требуется определить организационный и технологический процесс разработки. Нам необходимо выпустить три релиза без бюджета

**Рассмотренные варианты:**

1. **Каскадная модель:** Последовательные фазы без возможности быстрой адаптации к изменениям требований
2. **Kanban:** Непрерывный поток задач с ограничением незавершенной работы, но без фиксированных временных рамок
3. **Scrum:** Итеративная разработка с фиксированными спринтами, планированием и регулярными ретроспективами   

**Решение:**

Выбран Scrum

**Обоснование:**

- **Контроль дедлайнов:** Фиксированные 2-недельные спринты задают понятный ритм и позволяют декомпозировать задачи для своевременного выпуска MVP
- **Ежеспринтовая постановка целей:** В конце каждого спринта формируется рабочий результат, что позволяет сразу гаходить ошибки и корректировать путь
- **Синхронизация и ретроспективы:** Для команды регулярные встречи и ретроспективы помогают быстро устранять блокеры и отслеживание скрытых проблем
- **Бесплатные инструменты:** Спринты, бэклог проекта и доска ведутся на бесплатных сервисах   
  
**Последствия:**

- Длительность спринта фиксируется на 2 недели
- На каждое планирование итерации формируется список целей для каждого члена команды с оценкой трудоемкости задач
- В репозитории поддерживается модель ветвления - задачи спринта реализуются в отдельных ветках с обязательным Code Review и проверкой автотестов перед слиянием в master
