**ADR: Стратегия хранения пользовательского контента**

**Дата:** 12 ноября 2026 г.

**Статус:** Предложено

**Контекст:**

Пользователи BestPlace загружают фотографии мест в форматах PNG и JPEG размером до 10 МБ. Необходимо обеспечить хранение файлов, серверную проверку и доступ с учётом модерации. Решение должно соответствовать микросервисной архитектуре и учитывать рост объёма контента и ограниченные ресурсы проекта.

**Рассмотренные варианты:**

1. **Файловая система сервера:** Проста на старте, но усложняет совместный доступ к файлам при нескольких экземплярах сервиса.
2. **MySQL, поля BLOB:** Хранение файлов увеличивает размер БД, нагрузку на неё и объём резервных копий.
3. **S3-совместимое хранилище:** Отделяет файлы от реляционных данных и предоставляет стандартный API для работы с ними.

**Решение:**

Использовать S3-совместимое хранилище для фотографий и отдельный сервис **filestorage** на Go для управления ими.

- Файлы хранятся в S3, а их метаданные в собственной схеме MySQL сервиса filestorage.
- Filestorage принимает изображения, проверяет фактический формат и размер, загружает их в S3 и возвращает `fileId`. Остальные сервисы сохраняют связи с этим идентификатором.
- Ключи доступа к S3 находятся только у filestorage. Сервис предоставляет API загрузки, удаления и получения временных ссылок на чтение.
- Хранилище закрыто от публичного доступа. Ссылки выдаются после проверки прав сервисом мест: до публикации автору и уполномоченным модераторам и администраторам, после публикации посетителям каталога.
- При замене фотографии создаётся новый файл. До одобрения изменений пользователям показывается прежняя опубликованная версия.

**Обоснование:**

- Работа с файлами и их проверка сосредоточены в одном сервисе.
- Хранилище и filestorage можно масштабировать отдельно от каталога.
- Браузер читает изображения напрямую из S3 по временным ссылкам.
- S3 API позволяет менять реализацию хранилища без изменения интерфейсов остальных сервисов при проверенной совместимости операций.

**Последствия:**

- Потребуется развёртывание и сопровождение дополнительного сервиса и хранилища. Конкретная реализация S3 выбирается с учётом доступных ресурсов.
- Для частично выполненных загрузок и неудачных удалений нужны повторные попытки и очистка лишних файлов. Файлы действующих черновиков, заявок и опубликованных мест сохраняются.
- При удалении файла из системы он удаляется не сразу, а помечается как deleted. Полное удаление происходит после 3 месяцев.
